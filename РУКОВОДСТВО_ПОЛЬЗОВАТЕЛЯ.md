# Руководство пользователя EvilOSX (полное)

> **disclaimer / предупреждение:** EvilOSX — это инструмент удалённого администрирования (RAT) и набор эксплойтов для macOS/OS X.
> Использовать его можно ТОЛЬКО в законных целях: на собственных машинах, в изолированных лабораториях, для пентеста с письменного разрешения владельца системы.
> Несанкционированное применение против чужих систем является уголовным преступлением.

---

## 1. Что такое EvilOSX

EvilOSX — «злой» RAT (Remote Administration Tool) для macOS, написанный на чистом Python.
Заражённые машины (bots / боты) устанавливают исходящее соединение с нашим сервером
и выполняют его команды. Соединение **всегда исходящее** (bot → server), поэтому
сервер не может «узнать», что бот офлайн, пока тот сам не напишет.

Взаимодействие скрыто: команды передаются внутри HTTP-страниц **404 «File Not Found»**
(методика «Hiding In Plain Sight»). Модули отправляются сжатыми через zlib и работают
на стороне бота чистым Python (без внешних зависимотов на целевой машине тоже).

## 2. Требования и установка

### 2.1 Что нужно

- **Операционная система сервера:** любая с Python (тестовая среда здесь — Windows).
- **Python:** 2.7-ветка **или** 3.7+.
- **pip** для установки зависимостей.

### 2.2 Зависимости сервера

Устанавливаются из `requirements.txt` проекта:

```bash
sudo pip install -r requirements.txt
```

> На хосте, где мы работали (Windows), зависимости включали
> `pycrptodomex`, `pyside2`, `python-dateutil`, `future`, `colorama` и т.п.
> Для GUI требуется **PySide2**; для CLI — **urwid**.

## 3. Запуск сервера

Сервер запускается из корня проекта:

```bash
python start.py [опции]
```

### 3.1 Параметры командной строки

| Флаг | Описание |
|------|----------|
| `-p, --port <N>` | Порт, который слушает сервер (иначе спросит вручную). |
| `--cli` | Запустить интерфейс командной строки (urwid) вместо GUI. |
| `--builder` | Режим сборщика: создать «launcher» для заражения цели и выйти. |
| `--no-banner` | Не печатать ASCII-баннер (удобно при SSH / на маломощных машинах). |

### 3.2 Обычный запуск (GUI)

```bash
python start.py
# или задать порт сразу:
python start.py -p 1337
```

Сервер ответит и покажет GUI (PySide2), где боты появляются по мере подключения.

### 3.3 Запуск CLI (для SSH / без GUI)

```bash
python start.py --cli --port 1337
```

CLI построен на urwid: верхняя панель — вывод, нижнее поле — ввод команд.

## 4. Режим сборщика: как заразеть цель

Чтобы получить исполняемый файл-запускатель (**launcher**) для цели:

```bash
python start.py --builder
```

Сборщик задаст по шагам:

1. **Server host** — адрес (IP/домен) нашего сервера, куда будет стучаться бот.
2. **Server port** — порт сервера.
3. **Where should EvilOSX live?** — папка на цели (пустое = скрытая
   `~/Library/Containers/.<RANDOM>`).
4. **Launcher** — какой запускатель использовать (их перечислят):
   - например `bash`, `dylib`, `applescript`, `osascript`, `jar`, `python` — по умолчанию индекс `1`.
5. **Loader** — какой загрузчик (перечислят с описанием):
   - например `launch_daemon`, `run_script`, `start_service`; по умолчанию индекс `0`.
6. **Опции выбранного loader** (если они есть, напр. имя LaunchAgent / путь скрипта и т.п.).

После подтверждения сборщик запишет файл:

```
data/builds/Launcher-xxxxxx.<ext>
```

Этот файл нужно **доставить и запустить на целевой macOS-машине** (например через
свой одноцелевой макро-генератор, Rubber Ducky или phishing).

> **Важно:** из-за того, что payload создаётся уникально под каждую систему,
> **сервер должен быть запущен**, когда бот подключается впервые.

## 5. Обзор интерфейса и список команд (CLI)

После входа в CLI можно вводить команды. Всё, что **не** совпадает со служебными
командами ниже, будет выполнено на подключённом боте **как команда shell** (системный вызов).

### 5.1 Полный список команд

```
help                 — показать это меню команд.
bots [страница]      — список доступных ботов (по 10 на страницу).
connect <id>         — выбрать бота для интерактивной работы (обязательно перед «use»).
modules              — показать список доступных модулей.
use <module_name>    — запустить модуль на выбранном боте.
stop <module_name>   — попросить модуль остановиться (поддержка «Stoppable»).
useall <module_name> — задать модуль, который выполнится на всех ботах.
stopall              — сбросить глобально заданный модуль.
clear                — очистить экран.
exit / q / quit      — закрыть сервер и выйти.
```

### 5.2 Типовой порядок работы

```
> bots
> connect  3a2f1           # id бота (или любой выбранный)
> modules                    # посмотреть доступные модули
> use   screenshot           # запустить модуль на выбранном боте
> use   micro_on_background  # ещё один, если нужно
> q                          # выйти
```

## 6. Модули: подробный справочник

Всё, что выдаёт модуль, сохраняется в директорию `data/output/`.

### Сбор информации о системе

#### `get_info`
Собирает базовую информацию о боте. Запрашивает секретный вопрос при настройке.
При обработке ответа форматирует данные в аккуратный блок «ключ: значение»
и устойчив к отсутствующим полям.

---

### Хранилище / учётные данные

#### `clipboard` (буфер обмена)
Читает буфер обмена бота или синхронизирует его N раз. Настраивается:
- **количество чтений** (пусто = 1);
- **имя локального файла** для сохранения (пусто = случайное `<RANDOM>.txt`).

Умеет декодировать и текстовые, и base64-данные, убирает служебный префикс `[clipboard] ... - `, обрабатывает пустой буфер.

#### `chrome_passwords`
Извлекает сохранённые пароли Chrome. Улучшено: перебирает **все** профили Chrome,
ищет файлы `Login Data`, аккуратно обрабатывает отсутствующие профили
и корректно работает с шифрованием/расшифровкой. Результат выводит построчно.

#### `decrypt_mme`
Расшифровывает данные macOS **Messages (iMessage)**. Улучшено: лучше определяет
каталог MME-данных, делает копию базы **до** изменения (безопасность),
и понятно выводит результат.

#### `icloud_contacts`
Получает контакты iCloud по токенам. Улучшено: устойчиво к HTTP-ошибкам и
таймаутам, умеет задать имя выходного файла и аккуратно форматирует список контактов.

#### `phish_itunes`
Фейковая страница iTunes для **фишинга** пароля iCloud/Apple ID. Улучшено:
проверяет формат введённого Apple ID/email, защищается от пустых сообщений,
корректно выводит результат фишинга.

---

### История и файлы

#### `browser_history`
Вытаскивает историю браузера. Улучшено: поддерживает Chrome (SQLite `History`) и Safari,
даёт задать **число URL** и **имя файла**, сохраняет результат в `data/output/`
и аккуратно его печатает.

#### `download`
Скачивает файл или папку с бота на сервер. Настройки:
- путь к файлу/папке на боте;
- размер буфера (пусто = 4096);
- имя локального файла (пусто = имя удалённого basename).

Улучшено: валидация пути (без выхода за `data/output/`), проверка существующего файла,
подсчёт **MD5** на сервере и на боте (сверка целостности), поддержка бинарных чанков
и base64. Папки компрессируются на боте.

#### `upload`
Загружает файлы на бота. Улучшено: проверка существования локального файла **до*
отправки, флаг рекурсивной загрузки папок, понятная обработка ошибок.

#### `get_backups`
Перечисляет iTunes/iOS-бэкапы на боте. Улучшено: валидация количества, верхние
лимиты, чёткий листинг доступных бэкапов.

---

### Запись и захват

#### `screenshot`
Делает снимок экрана. Настройки:
- имя локального выходного файла (пусто = `<RANDOM>`);
- формат **png/jpg** (пусто = png);
- **задержка** перед снимком в секундах (пусто = 0) — чтобы успеть открыть нужное окно.

#### `webcam`
Фотографирует бота через веб-камеру. Перед запуском предупреждает, что загорится
зелёный индикатор. Улучшено: выбор **номера камеры** (0 — встроенная, 1 — внешняя)
и **числа снимков**. Зовёт ОСТОРОЖНО — включается светодиод.

#### `microphone`
Записывает микрофон в MP3 (через AVAudioRecorder). Настройки:
- длительность записи, сек (пусто = 5);
- удалённая выходная папка (пусто = `/tmp`);
- удалённое имя файла (пусто = `<RANDOM>`).

Улучшено: валидация времени, информирование «лучше использовать download» для забора MP3.

### Атаки и эксплойты

#### `slowloris`
Медленная DoS-атака (уязвимы Apache 1.x/2.x, dhttpd; nginx — нет). Улучшено:
- host, **порт**, **socket timeout**;
- **длительность** (пусто = бесконечно, потолок 86400 сек);
- **число сокетов** (пусто = 200, макс. 2000);
- **HTTP payload** (пусто = обычный GET).

Многопоточная: держит много соединений одновременно. Установки валидируются,
а вывод показывает статистику (host:port, сокеты, длительность).

#### `CVE-2015-5889`
Локальный эксплойт привилегий для OS X. Улучшена защищённая логика: корректный
setup и обработка ответа на серверной стороне. (Требуется определённая версия ОС.)

#### `CVE-2020-3950`
Локальный root-эксплойт для **VMware Fusion <= 11.5.2**. Два компонента:
- **bot** (`server/modules/bot/CVE-2020-3950.py`) — код эксплойта, выполняемый на цели.
- **server** (`server/modules/server/CVE-2020-3950.py`) — менеджер модуля.

Идея: перезаписывает/управляет `sandbox-helper` с правами `root:wheel:rwx`;
при падении бинарника выполняется наш скрипт как root; по пути создаётся
песочница-«путаница путей» (path confusion), после чего выполняется `/bin/bash`
с флагом `-p -c id` (setuid-оболочка).

**Мы также исправили файл бота**: убрали смесь табов/пробелов и поправили
старую литеральную запись `0755` → `0o755` (чтобы код работал на Python 3).

## 7. Устройство «внутри»: как всё связано

Заражение делится на 3 части:

1. **Launcher** — запускается на цели и запускает stager.
2. **Stager** — обращается к серверу за **loader**-ом (который решает, КАК
   загрузится payload: launch_daemon / run_script / start_service).
3. **Loader** — получает уникально зашифрованный **payload** (AES-256) и отдаёт его
   обратно в stager, тот выполняет.

Коммуникация:
- **GET** — бот забирает команды (спрятаны в странице 404).
- **POST** — бот отправляет ответы на сервер.
- Действие **строго исходящее** (бот сам инициирует).
- Модули передаются как **сжатый zlib** Python-код + набор опций.

Лоадеры (`bot/loaders/`):
- `launch_daemon` — сохранение/запуск через launchd (LaunchAgent/Daemon), watchdog и самовосстановление;
- `run_script` — выполнение скриптов разных форматов (`.sh`, `.bat`, `.ps1`, `.rb`);
- `start_service` — устойчивая работа со службами.

## 8. Советы и ограничения

- **Офлайн-боты невидимы**: сервер не узнает об отключении бота, пока тот сам не напишет.
- **Payload уникален**: сервер обязан работать при первом контакте бота.
- **Персистентность** достижима через launchd-лоадер (запуск при загрузке).
- **Антивирус**: коммуникация шифрованная (AES-256), модули — чистый Python, без
  сторонних зависимостей на цели.
- Если модулей не видно в `use`, выполните `modules` — список читается из
  `server/modules/server/*.py`.
- Всё сохраняется в `data/output/`.
